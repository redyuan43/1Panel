# 自然语言 Skills 脚本策划

## 实施前契约

开放式创作意图、镜头取舍和自然语言修改不能由关键词拼接可靠完成，采用一个
`script_planner` 语义角色。素材校验、时间轴验证、版本控制、导出和生成衔接均用普通代码。
不引入多 Agent，不执行模型返回的工具或代码。

- `AgentCatalog`：单角色、AI Router 语义模型、只读文字权限；每轮最多两次模型调用。
- `TaskEnvelope`：原始需求、当前时长/素材用途、当前草稿及本轮修改；有明确大小限制。
- `CapabilityManifest`：分别报告配置、真实结构化结果验证和最近调用健康状态；模拟不能替代真实验收。
- `ResultEnvelope`：终态、脚本、选用规则及来源摘要、模型请求 ID、耗时、调用数和首个错误。
- 生命周期：created → preflight → matched → dispatched → running → validating →
  completed / needs_context / failed / cancelled。重启把未完成文字策划标为失败，不盲目重发。
- 一次请求先语义选择 Skills，再加载对应的安全规则写脚本；显式选择 Skills 时只需第二步。
- 基线验收：一名策划者完成相同需求；无需多 Agent 性能假设。验收涵盖广告、短剧、
  参考素材、自然语言修改、格式错误、取消、重启、重复操作和脚本版本绑定。

## Skills 边界

原项目归档有 20 个目录，包含别名。运行时只使用原项目已经提炼的
`prompt_profiles.json`，来源摘要和原 Skill 名称见 `app/skill_sources.json`。
界面将明确显示“Skills 安全提炼规则”，不是声称执行了归档中的 `videogen.py`。
缺乏对应安全规则或未实现生成能力的条目标记为仅归档，不假装可调用。
归档脚本、第三方服务、凭据读取指令都不进入模型工具集。

## 生成权限

策划、修改、保存和批准脚本不调用 ComfyUI、MiniMax 成片接口或外部素材工具。
素材仅提供用户选择的文件名称和用途；文字策划不声称看过图片或听过音频。
生成提示词由已校验的分镜编译，不执行自然语言中的 shell、URL 或工具要求。
脚本批准后进入原工作室设置，用户仍需点击创建任务，并遵守原阶段确认。
当前单条 H3 视频时长仍为 4–15 秒，不把多镜头描述擅自拆成多次生成或拼接。

## 配置与上线

默认不配置文字模型，不会用固定模板冒充自然语言策划成功。
`H3_SCRIPT_ROUTER_URL` 只允许本机 AI Router 的 `/v1/chat/completions`。
`H3_SCRIPT_MODEL` 为语义模型 ID，默认 `siyuan/auto`，不选择物理 GPU。
`H3_SCRIPT_CREDENTIALS_FILE` 指向 Git 外的 JSON，包含 `router_key` 和 `readonly_secret`。
使用无媒体生成授权的只读账号，服务端签署只读请求上下文；凭据不进入提示词或浏览器。
接入文字模型、读取既有私有凭据、发送真实请求和重启体验服务须另行确认。
视频处于模拟模式时，文字策划可以独立接入真实模型，界面必须分别标示两种状态。

## 页面与 API

- 主入口位于原工作室的“原始提示词”正下方：自动选择 Skills 并策划 → 显示选择理由和脚本 → 自然语言补充/修改 → 确认后原地回填。不需要跳转到独立脚本页。
- 自动请求始终发送空 `skill_ids`，由后台文字模型选择；标记 `baseline` 的两项固定基础规则单独显示，不能冒充模型选择。前端不做关键词选 Skill 或脚本回退。
- 原文在确认前保持不变；回填后仍保留原始需求和调用记录。修改使用原需求与上一版脚本，不把已编译提示词重新当成需求。
- 待补充问题、未确认脚本、变更的提示词/时长/模式/声音配置会阻止创建。可显式恢复原文，不使用该脚本；原有手写提示词直接创建流程仍保留。
- 脚本请求复用稳定操作标识；结果不明时支持重试原请求，刷新页面后也保留该标识。不会自动重发模型请求。脚本和版本通过页面 URL 恢复。
- 复用既有 `/api/scripts`、认证、轮询、版本确认与创建时校验。未接入后台或只读文字模型时，原地入口明确禁用，不伪造自动选择结果。
- `script-studio.html`：原始需求、可选 Skills、素材事实、分镜编辑、自然语言修改、版本确认与 Markdown/JSON 导出。
- `GET /api/scripts/options`：15 个规则组，关联原有20份归档；13组可用于安全文字策划，2组仅归档。别名不计为独立执行能力。
- `POST /api/scripts`：稳定 `operation_id` 与 `brief`。状态持久化在独立 `script-plans.sqlite3`；HTTP返回不代表模型已完成。
- `POST /api/scripts/{id}/{save|revise|approve|cancel}`：稳定操作标识与精确版本，阻止重复调用、过期操作和未解决问题的确认。
- `GET /api/scripts/{id}/export`：仅导出本版本有效草稿，不把失败修改之前的旧草稿冒充新版本。
- 原工作室接收 `script_plan`、`revision` 查询参数，仅预填；创建项目时服务端再次核对批准版本、内容摘要及生成约束。
- 沿用工作室认证与 CSRF 防护；只读模型凭据不下发浏览器。未部署新后端时，独立页面链接保持隐藏，原地入口显示未接入并禁用。

每轮最多2次模型调用，最多2轮策划同时运行，最多20个在途策划；这不是视频任务并行调度。
取消会停止本地等待和后续调用，但不能保证上游已开始的推理立即停止计费。
服务重启后的未完成策划标为失败，不自动重试。当前轮仅携带原始需求、最近草稿和修改要求；不自动扩展为无限聊天历史。
