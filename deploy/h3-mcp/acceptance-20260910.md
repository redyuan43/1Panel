## 已实现的保护

- 四配方默认 A4，固定 15 秒、480×864、24fps、原生音频；没有扩展高清、参考视频或并发。
- 提示词确认与开始生成分开；审批绑定任务、版本和输出，改稿后必须重新确认。
- 每次写入使用同一 Studio 事务和操作回执；创建响应丢失可只读按原 `operation_id` 找回。
- 当前提示词、原始需求、来源和历史分别保留；成型原文可强制逐字一致。
- 客户端优先本地创作 Skill；服务端仅返回既有指导，不额外调用策划模型。
- 服务端校验固定配方、运行版本和最终执行绑定；不相信客户端自行声明的资格。
- 客户端 Token、内部连接器密钥和管理身份分开；查询、下载和写入校验账号归属。
- 工具没有任意 HTTP、Shell 或 GPU 操作；输入、错误和审计避免泄露秘密。
- Control/Studio 都有写入与生成开关；能力结果取两侧限制，不能把 GPU 空闲描述成可提交。
- 查询和人工评价不会推进后续步骤；运行任务不依赖聊天保持连接。

## 候选检查发现并处理的问题

1. 当前 Control 已有 MCP `1.26.0`；不将其他功能的 SDK 升为 `2.2.0`。
   最终候选复用线上 SDK、SSE 和核心依赖的精确版本。
2. 宿主的严格 `umask` 把声明的只读代码权限变为仅 root 可读，导致候选的
   `10001:10001` 用户不能导入模块。准备器现在只对新建候选目录/文件显式设置
   `0755`/`0444`，并增加严格掩码回归；不修改全局掩码、源路径或生产权限。
3. Studio 的执行元数据原先会丢弃 `admission_reason`，候选补齐该字段，避免等待原因消失。
4. 冻结配方在保存和开始时检查还不够；执行图准备完成、提交 Fleet 前再次核对运行绑定。

早期 Control r1/r2/r3 和 Studio r1/r2 都不是最终交付版本，不部署它们。
构建清单是准备时的不可变记录，不回填“已构建/已部署”；后续验证单独记入交付报告。

## 仍需完成的上线验收

1. 确认维护窗口后再复核队列，备份持久状态、配置和镜像，仅切换 Studio 与两个 Control。
2. 建立最小权限客户端和服务端内部密钥，默认关闭生成；密钥不放入 ZIP、聊天或 Git。
3. 通过 WorkBuddy 支持的安装入口和原生私密凭证表单接入；不写私有加密数据库。
4. 在真实客户端创建明确标记的验收草稿，展示并确认提示词，停在生成之前；断开重连找回同一任务。
5. 经授权使用已有视频进行单独的导入验收，明确标为 `fixture_import`，保留原项目和原文件。
   验证真实预览、Range 播放、下载及人工评价绑定；不得冒充本任务新生成的视频。
6. 对账新增 GPU 提交为零；以上通过后才开放 MCP 的正式生成开关，不自动提交任何任务。

本次不重跑四配方成片或短测，不要求用户重新评价旧样片。
回滚先关闭 MCP 新写入与生成，保留既有任务查询和对账；不删除历史、不重复提交，
存在需要新版本对账的任务时不贸然恢复旧版本。详细步骤见同目录 `README.md`。
