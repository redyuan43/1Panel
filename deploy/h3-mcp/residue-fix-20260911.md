# 取消后模型驻留清理

## 已核实根因

取消路径只写 cancelled 并清理输入，没有统一关闭监听和结束内存对账；正常终结才写入 warm。后续清理入口依赖 warm 存在，因此取消后的模型驻留无记录，冷启动显存门禁始终不通过。

2026-09-11 13:23:36 只读迁移盘点：仅一条带后端绑定的 cancelled 遗留，无 error/missing 遗留。任务 `a547ac0dff3046eda025bc7ece73055d`，原 single-a4 PID/start_ticks 与当前一致。唯一等待任务为 `2d3f113d2c3d43f8b161ac53b25378a1`，未提交给后端。

## 修复边界

- 终态与待清理回执同事务持久化，取消后统一结束监听、对账及审计；不把取消当作成功热模型。
- 遗留恢复不伪造采样，不覆盖首个错误或历史 OOM；不把恢复时的其他任务内存计入旧任务。
- 按 GPU UUID 核查所有同卡队列、数据库忙任务及固定进程身份，确认空闲后才发送一次 `/free`。
- `/free` 的 HTTP 200 不是释放完成；通过后端显存及进程显存有界轮询确认。请求结果未知时只查询，不自动重复发送。
- 保留72GiB、Swap、PSI、显存和稳定窗口保护；不重启GPU worker，不改变配方资格。
- 旧进程已消失的回执安全退役，不清理新进程；旧取消不能覆盖后续健康任务的热模型状态。
