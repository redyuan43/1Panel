# AI Router 专用规则

## 开始前必读

先阅读 `docs/current-state.md`，再根据任务读取相关配置、源码和测试。该文档是导航和
带日期快照，不替代当前代码、运行配置或生产证据。

## 路由不变量

- 用户显式指定的模型、路由指令或持久绑定不得被静默替换、降级或跨模型压缩。
- 上下文、模态、工具协议、授权、隐私、预算和容量都是硬约束；不满足时在推理前
  返回稳定的非 2xx 状态与业务错误码，不截断输入或路由到不兼容端点。
- 自动路由、显式模型、提示指令、客户端绑定、会话亲和和时间窗口是不同机制；
  诊断时逐层记录实际命中的约束与优先级。
- 时间窗口只改变配置声明的云端 Flash 候选顺序，不等于绕过本地优先、显式选择或
  其他硬约束；是否生效以运行时设置为准。
- 服务端压缩不得假设客户端知晓摘要状态。显式/定向模型上下文不足时应明确失败；
  仅自动路由且账号、策略和目标共同允许时才可进入压缩流程。
- 对外 `siyuan/auto` 身份与内部真实端点分离；公开错误、响应体、SSE 和响应头不得
  泄漏内部模型或基础设施标识，内部审计仍保留真实路线。

## 诊断证据

- 按客户端传输、Router 接收、策略决策、容量租约、上游请求、推理完成六层追踪。
- 使用精确 request/trace ID 和时间戳关联审计；相邻请求、UI 状态或单独 HTTP 200
  不能替代目标请求证据。
- 配置默认值、运行时覆盖、容器源码、镜像 revision 和 Git 工作区分别核验。
- 检查生产容器时只输出必要元数据和哈希，不打印完整环境或密钥。

## 修改与测试

- 保留当前混合工作区中的无关修改；只编辑任务涉及的文件和测试。
- 优先运行目标测试，例如 `python3 -m pytest -q tests/<相关文件>`；扩大回归前记录
  已知基线失败，不能为凑全绿修改无关策略。
- 路由行为变更至少覆盖 Chat 与 Responses、流式与非流式、显式/自动选择、错误公开
  文案以及审计终态。仅文档治理不要求发送真实模型请求。
- 变更路由契约、配置、错误码、身份边界或部署流程时，同步更新
  `docs/current-state.md`。

## 生产边界

- 构建候选前记录精确基础镜像；替换服务前再次核验运行镜像，基线漂移即停止。
- 发布必须使用独占锁或等价串行机制，逐服务 drain 到活动请求为零后替换，并验证
  image ID、revision、源码哈希、健康、draining 状态和重启次数。
- 生产部署、真实模型调用、配置写入、路由切换和服务重启均需明确授权；代码修改或
  测试通过不代表已经部署。
