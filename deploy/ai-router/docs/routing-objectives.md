# 简单策略与性能迁移

策略设置默认打开简单页面，提供成本、效率、质量三个选项。当前生效策略和正在编辑的策略分别显示；修改表单不会立即改变生产配置。点击“验证并应用”依次保存草稿、验证并激活，验证失败保留原生产策略。简单页与高级页编辑同一份草稿，切换页面或策略不清空其他参数。

## 策略与账号

- 成本优先：本地优先，保留会话缓存。开启“仅使用本地模型”后，云端始终被排除，包括明确指定云端模型的请求。
- 效率优先：本地满足要求时继续使用；上一轮严重等待或同类请求持续降速时，在下一轮评估替代模型。
- 质量优先：按通用、代码、图像的管理员顺序选择已获准且能力合格的高质量模型；允许配置 Flash 兜底。

账号页面可选“继承全局／成本／效率／质量”，列表显示实际策略及来源。账号和全局的“仅本地”约束取并集。模型权限、健康、上下文、输出预留、预算和能力过滤始终先执行；质量池的授权不自动开放给成本模式。明确模型、定向口令、手动固定不被速度优化覆盖。

旧配置没有 `routing.objectives` 时保持旧规则。启用该模块后默认模式为效率；`observe_only` 可观察新决策而继续执行旧规则。

## WorkBuddy 长上下文与云端时段

默认模型目录向 WorkBuddy 声明 `contextWindow=1000000`、
`maxInputTokens=934464`、`maxOutputTokens=65536`。该声明只负责避免客户端在
196K 附近提前压缩，不等于一开始就使用百万上下文云模型。Router 仍先按请求的
真实 Token 数、输出预留、模态、工具能力和健康状态筛选端点；新会话优先选择
满足硬约束的本地模型，本地不满足要求或现有效率门槛触发时进入云端候选。
已有会话仍保留原有亲和性策略。Router 的压缩模式仍为
`explicit_only`，WorkBuddy 账号未显式授权时不会静默进行第二次压缩。

客户端仅修改输入/输出上限不会关闭 WorkBuddy 自身的压缩机制；这只能推迟
容量触发点，不能承诺接近新上限时也不压缩。目录中的输入/输出数值属于能力
声明，实际准入仍按所选端点的安全窗口与本次输出预留计算；当前两家 Flash 的
安全窗口均为 1,000,000，超限会拒绝路由，不截断原文。尚未新增统一入口的
1M 硬限制或专用超限错误码。

云端 Flash 对通用、代码和多模态三组执行同一严格时段策略：北京时间周一至
周五 `09:00-12:00`、`14:00-18:00` 只允许 `zhipu-glm-5.3-flash`；其余时间
只允许 `cloud-deepseek-v4-flash`（当前上游为 DeepSeek V4.1 Flash）。时段内
指定的云端不可用时返回错误，不跨厂商回退。明确指定模型、管理员固定和路由
口令仍保持原有优先级；效率档已有的严重等待、持续降速、收益门槛和冷却期逻辑
不变。

## 性能证据

通过现有请求收集数据，不额外发送测速请求。统计保存在共享 Redis 中，按端点、上下文区间、思考模式和缓存状态分组，每组保留最近 30 分钟、最多 100 条成功请求。

默认规则：

| 条件 | 默认值 |
| --- | --- |
| 严重等待 | 上一轮真实 prefill 超过 180 秒；缺少指标时使用上游首个有效输出等待，并注明来源 |
| 持续降速 | 最近 3 条可比较有效样本至少 2 条低于 10 Token/秒，或低于近期基线的 50% |
| 有效吞吐样本 | 输出至少 128 Token、生成阶段至少 5 秒，有可靠 Token 计数 |
| 基线 | 至少 5 条；排除最近 3 条降速判断样本 |
| 普通迁移收益 | 包含目标模型重新处理历史的成本，预计至少节省 30% 且 15 秒 |
| 冷却期 | 600 秒；硬性不可用或能力不符不受此软限制约束 |

排队、首个有效输出、首段正文、生成速度和可用的真实 prefill 分开记录。心跳、角色字段和仅工具 ID 不计为输出；思考耗时不称为 prefill。无目标性能证据时不宣称更快；严重等待后允许按 Flash 偏好顺序尝试，审计标为待验证。预计输出量采用可比较历史样本的中位数，无样本时为 1,024 Token，并受本次请求预算约束。

第一版只影响下一轮，不取消当前生成、不并行竞速、不因慢而重放工具调用。

## Token 计数

AI、Edge 的文本 Chat 请求使用各自后端的 `/v1/chat/completions/render`，按实际模型、工具解析及聊天模板计数。缓存键包含请求格式、模型、模板和 tokenizer 版本。未覆盖协议、图像或后端计数不可用时明确标为估算，仍检查输入加输出预留。

本次历史请求的计数差异主要来自工具历史中 JSON 字符串参数触发原共享模板计数失败，随后退回整份 JSON 估算。另有 53 Token 差异来自流水线归档按键排序；从同次路由归档恢复原工具字段顺序后，两次重算均与对应后端 usage 完全一致：上一轮 AI 为 127,633，本轮 Edge 为 128,010。工具字段顺序也纳入计数缓存键。没有使用固定折扣、截断历史或缩小输出预算绕过容量限制。
