# Redis 后台存档

## 保证范围

Router 将加密事件写入独立 Redis，收到确认后继续请求；不等待 AOF 刷盘或正式存档完成。
重启、强制终止或重建 **Router API 容器**不影响已经入队的事件。
后台消费者退出后可以重放；正式存档与事件去重凭据同一 SQLite 事务提交，确认消费后才能删除 Redis 数据。
运行中的模型调用不会自动重发，尚未成功入队的最后一段输出也不保证恢复。

Redis 必须独立保留。不要删除其数据卷、清空数据库或设置会驱逐队列数据的 eviction 策略。
当前部署使用 `noeviction`，AOF 每秒刷盘；本方案不保证 Redis/整机异常退出时零丢失。
不更改现有 AOF 策略，也不重启 Redis、V100 或 LMCache。

## 组件和失败行为

- `AI_ROUTER_ARCHIVE_QUEUE_ENABLED=true` 启用，默认 false 保留同步兼容路径。
- `archive-worker` 是独立 Compose 服务，两个 API 共用一个工作进程；宿主持久目录的文件锁防止重复启动消费者。
- 每个请求拥有 FIFO 队列。大正文加密后按内容摘要保存，排队期间相同正文只存一份；确认最后一个事件后清理引用。
- 序列化/加密使用独立的单线程有界执行器，计算任务使用两个线程；取消等待不提前归还仍在运行的线程名额。
- 入队等待上限默认 1 秒；失败沿用 `training_archive_unavailable`。未开始响应返回 503，已开始输出的流发送错误，不发送成功终止标记、不重跑模型。
- 内存队列默认上限 **512 MiB 加密正文/事件字节**，由 `AI_ROUTER_ARCHIVE_QUEUE_MAX_BYTES` 设置；Redis 对象开销另计。没有自动丢弃策略。
- 磁盘可用空间低于 2 GiB 时，消费者暂停写入并通知 API 拒绝新请求；已有事件继续保留。告警状态最多有一个心跳周期延迟。
- 数据库锁/磁盘等暂时故障退避重试，最多每 60 秒一次；解密、格式等坏数据连续失败 5 次后隔离该请求，不阻塞其他请求。
- 修复原因后，通过 `python -m ai_router.archive_worker --retry <request_hash>` 恢复隔离请求。
- WorkBuddy 的存档依赖索引在正式写入后才发布。索引未就绪时沿用完整客户端输入，不等待后台存档。

## 上线、回退和观察

先启动消费者并确认健康，再逐台排空 API 请求、启用队列并替换 API。
不得把共享工作区的全部未提交改动直接打包上线；发布包基于当前运行镜像，只应用本次补丁。
释放顺序为：上游完整读取/关闭、释放模型并发名额、保存必要会话状态、确认存档事件入队、完成审计与资源收尾。
流式预算结算在收尾处执行一次，并保留已测量的用量，避免重复结算或失败重试丢失用量。

回退时先排空启用队列的 API，等待队列为空，再关闭队列开关、恢复 API 镜像。
如果后台尚有积压，可以先恢复同步 API，但必须让兼容消费者继续处理原队列，不能清空它。
旧格式训练存档、导出和模型公共 API 保持兼容；去重表是增量表。

`/internal/training/status` 新增 `queue`：积压请求数/字节、最老等待时间、失败/隔离请求数、磁盘入队限制和消费者心跳。
请求阶段耗时新增 `archive_enqueue`、`token_count_offloop`。
上线后用自然流量观察 24 小时：按输入长度和并发量对比前置处理、TTFT 和输出后收尾时间，同时检查错误率和队列积压。
样本不足时仅报告当前样本，不宣称已证明全天或所有输入场景提速。

## CPU 测试

安装生产依赖及 `requirements-test-archive.txt` 后运行：

```sh
python -m pytest tests/test_archive_queue.py tests/test_usage_stream_contract.py
```

真实进程退出测试必须指向**一次性测试 Redis**，禁止填写生产地址：

```sh
ARCHIVE_TEST_REDIS_URL=redis://127.0.0.1:<test-port>/0 python -m pytest tests/test_archive_queue_process.py
```

测试模拟生产者入队后直接退出、消费者提交存档后在确认前被强制终止，再由新消费者恢复；不调用任何模型。
