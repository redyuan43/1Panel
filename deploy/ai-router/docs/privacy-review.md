# 输入保密旁路

本模块只观察输入意图，不拦截请求，不重写主模型消息，也不更换主模型或 worker。
通用内容安全和输出语义审核不在本轮范围内。

## 配置

在现有身份设置内新增 `identity.review`，默认值：

```yaml
identity:
  review:
    mode: "off"
    base_url: http://agx.taild500c8.ts.net:11434
    model: qwen3:4b-instruct
    sample_rate: 0.1
    requests_per_minute: 2
    timeout_seconds: 15
```

`backend` 缺省为 `ollama`，也支持直接连接 `llamacpp`：

```yaml
identity:
  review:
    mode: "off"
    backend: llamacpp
    base_url: http://agx.taild500c8.ts.net:8080
    model: Qwen36_35B-A3B-pruned-v2.gguf
    sample_rate: 0.1
    requests_per_minute: 2
    timeout_seconds: 60
```

这是待验收配置示例，不表示生产已启用。模型名称必须与现场 `/v1/models`
中的 ID 精确匹配，不能仅凭模型文件或启动参数判断可用。

配置通过既有内部设置 API 管理，控制台“策略设置”页签也提供了对应的表单
卡片（模式、后端类型、base_url、审核模型、采样率、限流、超时），不必再
手改 YAML 或直接调 API；`base_url` 与限流字段有较隐蔽的取值范围（私网地址
白名单、每分钟请求数只能是 1 或 2），页面会在保存前做同样的校验并给出提示。
合法模式只有 `off` 和 `shadow`，没有 `enforce`；完成离线评测不自动启用
生产旁路。启用须取得单独确认。切回 `off` 停止提交新审核，已执行的单次
审核受原超时约束结束。

共享本地模型池使用 `router` 后端，经专用内部账号进入统一容量管理：

```yaml
identity:
  review:
    mode: shadow
    backend: router
    base_url: http://127.0.0.1:4000
    model: huihui/Qwen3.8-27B-Q4-DFlash2
    sample_rate: 0.1
    requests_per_minute: 2
    timeout_seconds: 60
```

该后端只允许上述精确 loopback 地址，凭据从
`AI_ROUTER_PRIVACY_REVIEW_KEY` 环境变量加载，不写入设置或 Git。
账号必须为 `internal`，仅授权指定本地模型，防止递归审核和云端回退。
账号仍执行正常鉴权、限流、worker 租约和超时。审核请求使用独立会话，
原始请求和实际审核请求 ID 均可追溯。

直接后端仅接受 loopback 或本项目 Tailscale DNS 下的模型接口。
所有后端均不跟随重定向、不携带客户 Key、不使用 `auto` 或云端兜底，
不改变 GPU 模型服务启动参数。

## 处理流程

1. 公共请求通过客户端限额检查后，按服务端请求 ID 哈希采样。
2. 独立提取当前任务和必要历史；模糊包装、过长输入返回“不确定”。
   XML/HTML 标记用于理解来源，不赋予内容可信权限，也不修改原始消息。
3. 每个 API 实例最多保留一个审核任务；Redis 锁使多个实例合计最多一路。
   共享 60 秒窗口最多两次调用，繁忙或超额直接跳过，不建立长队列。
4. 调用前只读检查 AGX `/api/ps`。模型未驻留或上下文不是 4096 时跳过，
   不因旁路请求加载模型或改变上下文。
   `llamacpp` 则检查 `/v1/models` 和 `/slots`，只接受模型匹配、已知空闲且
   上下文至少 4096 的端点。任一 slot 繁忙或状态未知时不发推理请求。
   这是调用前的健康快照，并非与外部直接调用者共享的原子租约；单槽端点
   若用于持续生产审核，应专用或另设统一的准入层，不能宣称完全消除竞争。
   `router` 后端只读验证授权模型目录，随后通过 Router 的原子容量租约排队；
   不直连 worker，不绕过其他业务请求的占用信号。共享 GPU 仍有资源竞争，
   低频采样限制成本，但不能承诺对主模型吞吐完全没有影响。
5. Ollama `/api/chat` 使用固定分类提示词、JSON Schema、temperature=0、
   num_predict=128。输入采用保守的 3000 UTF-8 字节上限，给模板及输出留余量；
   不截断大请求再声称已完整判断。
   `llamacpp` 使用 `/v1/chat/completions`、JSON Schema、`max_tokens=128` 和
   `enable_thinking=false`，只接受 `finish_reason=stop` 的完整结构化结果。
   输入预算与原 Ollama 评测保持一致，不因 128K 启动参数自动扩大。
6. 结果仅为 `normal`、`internal_info`、`uncertain`，理由限制为枚举。
   无效 JSON、非完整响应、超时和连接故障均记录“不确定”，不影响客户回答。

审核调用默认 15 秒，可配置 1 至 120 秒。任务总超时为调用超时加 5 秒，
共享锁 TTL 为任务总超时向上取整后再加 10 秒，结束或取消时按 owner token
释放。默认配置仍分别为 15 / 20 / 30 秒。

## 审计

保留 `privacy_review` 审计事件，并在轨迹 SQLite 中新增独立
`privacy_assessments` 和 `privacy_feedback` 表，不写原始任务文本。
事件包含完整请求 ID、客户 ID、模式、策略版本、审核模型、来源类别、结论、
理由代码、耗时或跳过原因。当前输入解析状态同时进入内部路由轨迹
`privacy_input`，不出现在公共响应。

请求记录展开后的每轮可进入隐私审核详情；路由审计可按旁路结果筛选。
Auto 筛选同时包含 `auto` 与配置的公开模型别名，避免漏掉公共账号的观察结果。
详情显示自动结论、原因枚举、模型、策略版本、耗时、时间及实际审核请求 ID。
未采样或旧记录显示未审核，不等同于正常；跳过、不可用、待审核分别展示。
审核进程重启留下的待审核结果，超过该任务截止时间显示不可用。

人工隐私复核以追加方式保存，不覆盖自动判断，也不改变现有路由人工审核。
后台自动刷新完成请求的迟到审核结果。自动结果使用独立表和时间戳更新保护，
不会被主请求后续的轨迹写入覆盖。

旁路审核失败不能改写主请求状态，也不能输出固定身份声明。
身份直答仍执行既有客户端限流、用量和历史持久化流程。

## 离线评测

`tests/fixtures/privacy-review-luna.json` 是 Luna 生成、经格式校验的 200 条合成题，
正常任务与保密探针各 100 条。不包含真实用户完整历史或生产密钥。

只验证语料，不调用模型：

```bash
python3 scripts/evaluate-privacy-review.py \
  --corpus tests/fixtures/privacy-review-luna.json \
  --output /path/to/new-report.json
```

获准真实评测后添加 `--execute`。脚本串行调用，每次间隔一秒；启动前验证驻留，
连续三次不可用即停止。报告文件权限为 0600，不覆盖已有文件。
`--limit 4` 可先做小样本接口验证。退出码 0 仅表示评测执行完毕，不代表隐私通过。

新 llama.cpp 模型评测使用 `--backend llamacpp --base-url ... --model ...`；
脚本每题前重新检查空闲状态，忙时在客户端等待最多 `--idle-wait` 秒（默认 60），
超时则停止，不把评测请求排入繁忙模型。报告包含语料和策略提示词的 SHA256、
所有单题结果、`correct` 计数和 `passed` 门槛：全部完成且全部有效、判断正确。
正常题被拒绝、探针漏判和“不确定”都不计入通过，不能通过修改题目标签美化结果。
`tests/fixtures/privacy-review-luna-agx-holdout.json` 是独立生成的新增验收集；
判定理由不得作为 `context` 传入模型，避免给裁判提示标准答案。

2026-09-04 的 200 条短题评测结果：

- 全部返回合法结构。
- 正常任务 100/100 判正常。
- 保密探针 98/100 被识别，2/100 判为不确定，不能把这两条算作识别成功。
- 平均 803 毫秒，P95 848 毫秒，包含该次客户端到 AGX 的调用耗时。
- 这些是单一合成集、常驻模型、短输入、串行环境的观测，
  不代表长历史、多模态、持续生产负载或未知攻击下的效果。
