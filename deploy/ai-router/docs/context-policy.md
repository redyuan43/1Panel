# 可配置的长上下文策略

设置 → 策略配置 → 任务评估：填写目标 Codex 端点 ID（默认
`codex-pro-gpt-6-astra`），选择策略，保存草稿、验证并激活。
仅保存草稿不会改变运行行为。适用于暗号或显式指定该模型的请求，不改变普通 Auto 的选择。

## 两种策略

- **压缩后继续**：在原安全窗口超限时，先用配置的压缩模型处理旧历史，再调用原目标模型。
  该选项本身是管理员对该目标模型的压缩授权，覆盖全局压缩许可模式；不会改写客户端账号。
  复用加密会话 capsule 和历史边界机制，保留系统约束、近期对话与完整工具事务；摘要有损，
  并非原文的无损编码。过大的历史分段、顺序摘要再合并，单段有输入预算及输出预留。
  分段与合并次数有界，摘要阶段总等待上限 180 秒（不含队列等待）；不能安全压缩、
  近期内容过大、压缩服务不可用时明确报错，不截断。
- **扩展上下文，不主动压缩**：保留当前请求内容，使用设置的总预算。
  实际准入取管理员预算、注册表配置上限、选定账号该模型目录窗口的最小值。
  目录缺失或旧适配器不报告模型窗口时不扩大；不同账号不能共用另一个账号的上限。
  扩展失败不自动改走压缩，也不静默换模型；健康、授权、模态、配额和输出预留检查仍保留。

默认 **保持原有规则**，兼容旧配置，不自动启用压缩或提高窗口。

```yaml
context_policy:
  mode: legacy  # legacy / compact / extended
  endpoint_id: codex-pro-gpt-6-astra
  extended_context_tokens: 500000
```

`500000` 是待选择的预算，不代表已通过 50 万上下文实测。限制按
“输入估算 + 输出预留”计算，计数不保证与上游 tokenizer 完全一致。

## 边界与验收

- 切换为扩展模式不会还原已经摘要化的历史，也不会关闭 WorkBuddy 自身的压缩。
- 原客户端发来的大请求仍按现有限流机制计数；压缩和扩展都不绕过 TPM/RPM。
- 压缩模型需要可用的 Chat/JSON 摘要能力，处理过程中可能产生多次模型调用和额外耗时。
- 修改在源代码和离线模拟中验证。生产需部署 API、Control 和 Codex Adapter 对应模块；
  不需要重启 GPU 模型、Redis 或 LiteLLM，但部署前须确认范围并排空相关活跃请求。
- 真实长上下文验收应分别验证摘要关键事实、工具事务完整性、扩展模式全文关键位置、
  路由审计、流式结束和耗时；不能只看 HTTP 200。
