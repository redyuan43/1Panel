# 思源公开模型身份

AI Router 可以向普通 API 客户端隐藏真实模型、节点和物理 deployment，
统一使用公开品牌身份：

- 中文名称：`思源`
- 英文名称：`SIYUAN`
- 公开模型 ID：`siyuan/auto`
- 默认身份回答：`我是思源（SIYUAN），由思源智能路由服务提供的统一 AI 助手。底层模型、节点和路由实现属于内部服务信息，不对外披露。`

## 客户分级

- `public`：客户脱敏，授权目录仅有 `siyuan/auto`，请求兼容 `auto` 别名。
- `internal`：内部详细，保留真实模型目录、响应头和错误证据。

历史账号缺少 `disclosure_mode` 时按 `internal` 处理。管理台新建账号默认
使用 `public`，避免误建拥有完整模型权限的客户账号。

公共账号要求身份配置已启用且资料完整，否则直接返回
`public_identity_unavailable`，不会降级为内部输出。

公共账号启用后：

- `/v1/models`只返回`siyuan/auto`。
- `siyuan/auto`和兼容别名`auto`内部进入智能路由；真实模型 ID拒绝。
- Chat和Responses请求都会注入稳定身份策略。
- JSON、SSE、响应头和错误中的完整内部模型 ID、endpoint、deployment、
  GPU UUID及内部地址会被替换。
- 公共协议使用字段白名单，去除后端指纹、非公开计时和节点扩展字段；
  应用 JSON 中同名的 `model`、`timings` 字段不作为协议元数据修改。
- 明确询问当前助手底层模型、节点或路由时，由 Router直接返回固定身份回答，
  不调用 evaluator或底层模型。
- 管理台、路由审计和加密训练归档仍保留真实路由信息。

## 缓存影响

身份策略内容由配置生成固定 revision。相同 revision不会随请求变化，可以参与
后端prefix cache。修改名称、说明或身份回答后，已有会话下一轮需要对新的系统
前缀执行一次prefill，之后重新命中缓存。

## 安全边界

身份问题拦截只处理当前问题中指向本服务内部身份的高置信请求。已识别的
WorkBuddy 引用历史只作为背景；包装不完整、问题混合或存在歧义时，不因关键词
直接拒绝整项任务。解析视图不修改主模型收到的消息或会话历史。
真正的安全边界
仍是账号权限、响应头和错误 allowlist，以及 JSON/SSE 最终清洗。系统允许正常
讨论 Qwen、DeepSeek、GPT等通用技术名词，不会全局替换模型家族名称。

启用前应逐个真实端点使用多语言、间接询问、提示注入、工具参数和跨分片输出进行
验收。登记标识及编码形式清洗不是对所有语义泄露的保证，也不能阻止通过模型行为
进行统计指纹推断。独立输入旁路见 `privacy-review.md`，默认关闭；
输出语义审核和新的流式缓冲策略尚未实施。
