# GLM 费用与降本代码审查

范围：本次费用账本、XLSX 解析、管理接口与页面、WorkBuddy 前缀查询及审计接入。审查采用逐项检查代码、构造反例和回归测试；不扩大到现有模型策略、H3 或其他未提交工作。

| 发现 | 修复 | 验证 |
| --- | --- | --- |
| 旧审计把缺失输出写为零，直接用于费用会漏报未知消费 | 新审计标明输出是否来自上游；历史无证明的零输出保持未知 | 缺失/显式零/非法输出、真实 audit 接入测试 |
| Control 初始化假设所有运行替身都提供 SQLite，破坏原归档接口测试 | 仅在有持久账本路径时启动补记任务；无账本的费用接口返回不可用；取消时回收任务 | 原内容回退及 Control 审计测试 |
| 两个 Control 同时导入，查重与写入间可能竞争 | 导入事务先获取写锁，同号异内容整批回滚 | 双连接并行导入和批次回滚测试 |
| 历史补记与新请求同时完成，旧快照可能覆盖新费用 | 补记事务序列化；忽略旧通知及实测到未知的倒退 | 重试、乱序通知、补记、保存点失败恢复测试 |
| 单请求最后一次尝试的前缀结论可能显示在所有重试上 | 分析记录带版本和尝试号，仅附加到对应尝试 | 双尝试证据隔离测试 |
| 配置切换或原始历史变更可能被误判成已确认浪费 | 额外校验模型、配置指纹和原始前缀；不确定的变化保留待检查 | 配置变化/历史变化/正常增长/缺档测试；真实归档回放 |
| 归档不可读可能使费用详情变成 500 | 结构分析不可用时仍返回账目和用量 | 管理接口缺档测试和原有归档回退测试 |
| 浮点显示会把微小金额四舍五入为零 | 金额按整数精确计算、以字符串传输并保留有效小数展示 | 单价与金额精度测试、浏览器对账验收 |

实测费用、官方账单、缓存折扣和潜在价差分别表达；不会把大量正常输入、首次冷请求、长输出或未测量尝试认定为浪费。新增功能不触发美元预算预留或选模变化。

全量回归采用修改前隔离基线作比较，基线已有的注册表/旧断言问题单独留证，不通过修改无关策略来让测试变绿。最终测试结果、真实账单对账、归档回放、运行版本和发布记录存于本次本机验收目录；代码提交与生产镜像须分别核验。
