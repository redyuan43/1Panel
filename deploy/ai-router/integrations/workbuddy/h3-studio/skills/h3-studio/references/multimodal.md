# H3 多素材操作

仅使用已安装的受限本地 MCP 上传组件。远程九个业务工具仍走同一个认证 Control → Studio → Fleet 链路；不要创建另一套调度、修改客户端密钥或调用系统管理工具。

1. 明确素材用途。用户仅让助手“参考照片构思”时，可以看图写提示词，但必须说明照片未送入视频模型；用户要求“以这张图为首帧”时必须走上传链路。含糊时只问用途，不擅自选择。
2. 对明确附带的文件调用 `h3_upload_asset`，传稳定 `operation_id`、用途 `kind` 和该附件的精确 `local_path`。只允许附件目录；其他文件用 `choose_file=true` 让用户通过本机文件选择器明确选中。不扫描磁盘、不读取凭证，不抓取任意 URL。
3. 回执必须为 `ready`，包含 `asset_id`、`sha256`、格式、尺寸或时长。只存在文件名、本机路径或图像文字说明不算上传。上传超时后先用 `h3_get_upload` 查询同一操作；失败或处理中不得换操作 ID 盲目重传。
4. 调用 `h3_save_draft`，按用途传素材编号：首帧 `i2v/first_frame`；尾帧 `l2v/last_frame`；首尾帧 `fl2v/first_frame+last_frame`；参考 `reference/reference_image` 或 `reference/reference_video`；Hybrid 为 `hybrid/first_frame+last_frame+reference_image`。参考音频、视频内置音频及锁定音轨只能采用服务端当前支持的合法组合。
5. 多素材不传 `recipe_id=A4/B8`。读取返回的专用完整模型 `execution_profile` 和冻结版本。未注册或未验证的配置明确显示阻塞；不能用旧 T8、改规格、丢掉图片或改为文生来绕过。
6. 核对草稿的模式与每个 `input_assets` 的编号、摘要、用途和上传回执一致。展示精确提示词、输入卡、规格及执行配置，再暂停等待用户确认。“开启后台”不是生成授权。
7. 修改输入必须使用同一个任务的 `expected_revision` 新建输入版本，重新确认。保留旧文本和旧输出，不修改旧审批。确认页只读查看素材，不建立第二套上传流程。
8. 用户明确批准并生成后，依次调用确认与启动，始终携带当前版本和输出绑定。后台停用、入口关闭、模式未获资格、资源排队是不同状态；没有提交到执行链路时不能说“GPU 生成失败”。
9. 启动、加载、采样和解码由服务端负责。进程在线不等于模型已加载，模型已加载不等于资源可接单。客户端不选显卡、不调用启动脚本、不停止服务；后台管理只能由管理员在设置页操作。
10. 查询和视频审阅继续遵循主 Skill 的十秒间隔、版本绑定和人工评价边界。技术完成不代表画质通过，不自动高清、付费、换配方或重试。

参考视频以实际解码回执为准：当前完整模型需要恒定24fps输入，不能只看文件宣称的平均帧率。回执表明需要24fps素材时，保留原件和草稿并说明阻断；不得直接把30fps/VFR帧串按24fps送入模型、静默变速、裁短或谎称已经生成分析副本。可用的24fps原件直接作为模型输入，页面明确显示没有另造副本。高分辨率参考视频会增加整段解码内存，按服务端实际帧数和尺寸安全排队；不要用输出480×864替代输入尺寸估算。使用视频原声需要唯一音轨，不能擅自选择多音轨中的第一条。
